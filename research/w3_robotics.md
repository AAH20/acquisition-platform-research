### M&A Pattern Categories

1. **Platform Consolidation** — Defence-tech companies buying adjacent technology to fill product gaps (Anduril's acquisitions of Numerica for RF sensing, Blue Force for autonomous aircraft)
2. **Prime Contractor Partnerships** — De facto acquisitions via production awards (Forterra/Oshkosh ROGUE-Fires, $92M award)
3. **Pure M&A Scale Plays** — Ondas/DZYNE combining ISR, counter-UAS, and autonomous effects into one platform

### Cross-Border Dynamics

- **US consolidation:** Anduril, Ondas, SpaceX — deal sizes $200M–$875.8M
- **European consolidation:** Rheinmetall, BAE, Helsing — deal sizes €50M–€500M+
- **UAE/India expansion:** EDGE Group (Estonia), LAT Aerospace/Sharang Shakti (India)
- **Key trend:** Dual-use platforms command highest acquisition premiums because addressable market extends beyond Pentagon budgets

## Bottlenecks

### Technical Bottlenecks

| Bottleneck | Description | Impact on Valuation |
|------------|-------------|---------------------|
| **Sim2Real Transfer** | Policies trained in simulation fail in real-world deployment | High technical risk discount |
| **Distribution Shift** | Train/test distribution mismatch; real world changes over time | Requires continuous data collection |
| **Sample Efficiency** | RL requires millions of trials; real robot data is expensive | Capital-intensive R&D burn |
| **Low-Level Motor Control** | Language models don't solve dexterous manipulation | Limits general-purpose robotics |
| **No Standardized Benchmarks** | Unlike ML (MMLU, HumanEval), robotics lacks universal evaluation | Harder to compare companies, higher due diligence cost |
| **Deployment Complexity** | Integration, training, supervision requirements | Extends time-to-revenue |
| **Data Scarcity** | Proprietary datasets are moats but expensive to build | High barrier to entry, defensible advantage |

### Manufacturing & Supply Chain Bottlenecks

| Bottleneck | Description |
|------------|-------------|
| **BOM at Scale** | Prototype BOM irrelevant; BOM at 1,000 units determines viability |
| **Sole-Source Dependencies** | Custom actuators, proprietary sensors with no alternative suppliers |
| **Tariff/Trade Risk** | Component cost disruption from geopolitical shifts |
| **Manufacturing Partner Risk** | Contract manufacturing negotiations can change unit economics overnight |

### Regulatory & IP Bottlenecks

| Bottleneck | Description |
|------------|-------------|
| **Regulatory Certification** | 18–36 months, millions of euros (MDR, FDA, EASA, EU Machinery Regulation) |
| **IP Provenance** | Academic research, open-source firmware, government-funded work create murky ownership |
| **GPL Compliance** | Open-source license exposure in distributed hardware products |
| **Export Controls** | ITAR/EAR restrictions on cross-border defence robotics deals |

### Commercial Bottlenecks

| Bottleneck | Description |
|------------|-------------|
| **Customer Traction Gap** | Series A robotics companies may only have pilot agreements |
| **ROI Uncertainty** | Customer savings hard to quantify pre-deployment |
| **Procurement Cycles** | Government/defence sales cycles are long and unpredictable |
| **Integration Cost** | System integrators add time and cost to deployment |

## NP-Hard Problems in Robotics

Robotics acquisition targets should be evaluated on their algorithmic core. The following NP-hard and PSPACE-hard problems represent both technical moats and development risks.

### Computational Complexity Results

| Problem | Complexity | Source |
|---------|------------|--------|
| **Minimum Constraint Removal** (path with fewest obstacle crossings) | NP-hard (even with convex polygons) | Erickson & LaValle, AAAI 2013 |
| **Generalized Mover's Problem** (n linked polyhedra in 3D) | PSPACE-hard | Reif, 1979 |
| **Mover's Problem for 2D Linkages** | PSPACE-hard | Hopcroft et al. |
| **Shortest Path Among Polyhedral Obstacles** | NP-hard | Canny & Reif |
| **d-Optimal Motion for 2D Rod** | NP-hard | Asano et al. |
| **Multi-Robot Task Allocation** (MaxTaskWithinTotalBudget) | NP-hard | AAMAS 2021 |
| **2D Knapsack Problem** (reducible to task allocation) | NP-hard | Kulik & Shachnai |
| **Curvature-Constrained Shortest Path** | NP-hard | Reif & Wang |
| **Time-Optimum Path Planning in 3D Flows** | PSPACE-hard | Reif & Sun |
| **Movable Object Problem** (unspecified final config) | NP-hard | Wilfong |
| **Movable Object Problem** (specified final config) | PSPACE-hard | Wilfong |

### Implications for Acquisition Targets

1. **Motion Planning Stack** — Companies with efficient approximation algorithms for NP-hard planning problems have defensible IP
2. **Multi-Robot Coordination** — Swarm allocation is NP-hard; heuristic/approximation approaches are valuable
3. **Task Allocation** — Optimal multi-robot task allocation is intractable; companies with polynomial-time approximations for special cases have competitive advantage
4. **Path Planning** — Curvature-constrained and time-optimal planning hardness means proprietary solvers are key differentiators
5. **Due Diligence Question** — Does the target's software stack solve NP-hard problems with acceptable approximation ratios, or are they using brute-force methods that won't scale?
