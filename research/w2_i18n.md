## 1. i18n Support: ✅ Comprehensive System Exists

Hermes has a **mature, well-architected i18n system** across all surfaces:

### Python Backend
| File | Purpose |
|------|---------|
| `agent/i18n.py` | Core facade: `t()`, `get_language()`, `supported_languages()`, `resolve_language_id()`, `surface_catalog()` |
| `agent/i18n_layers.py` | Layer system: plugin packs > user overlay > bundled > English fallback |
| `agent/i18n_languages.py` | Language metadata: endonyms, RTL flags, picker list |

### TypeScript Frontend
| Location | Purpose |
|----------|---------|
| `apps/shared/src/i18n.ts` | Shared scaffolding: `mergeTranslations`, `formatPositional`, `unflattenMessages`, `LOCALE_ENDONYMS`, `RTL_LOCALES` |
| `apps/desktop/src/i18n/` | Desktop registry, runtime, catalog (9 languages bundled) |
| `web/src/i18n/` | Web context, catalog (17 languages bundled) |
| `ui-tui/src/i18n/` | TUI runtime, loader, keys (fetches from backend via RPC) |

### Architecture Highlights
- **3 surfaces**: `core` (Python), `tui` (terminal UI), `desktop` (Electron app)
- **Layered resolution**: plugin packs → user overlay (`$HERMES_HOME/locales/<lang>.yaml`) → bundled → English → bare key
- **Language resolution order**: `HERMES_LANGUAGE` env → `display.language` config → `en`
- **Plugin language packs**: `PluginContext.register_locale()` with endonym/RTL metadata
- **JSON-RPC bridge**: TUI fetches catalogs via `i18n.languages` and `i18n.catalog` methods
- **Validation**: `hermes plugins validate` checks language pack completeness against `_keys.tui.json` / `_keys.desktop.json`

### Supported Languages (17)
`en`, `zh`, `zh-hant`, `ja`, `de`, `es`, `fr`, `tr`, `uk`, `af`, `ko`, `it`, `ga`, `pt`, `ru`, `hu`, `ar`

## 2. Hardcoded Strings: ⚠️ Significant Gaps Remain

### By Surface

| Surface | Hardcoded String Matches | Severity |
|---------|------------------------|----------|
| **TUI** (`ui-tui/src/`) | 0 | ✅ Clean — uses i18n keys |
| **Desktop** (`apps/desktop/src/`) | 68 | ⚠️ Moderate — some UI labels hardcoded |
| **Web** (`web/src/`) | 76 | ⚠️ Moderate — page titles, placeholders, labels |
| **CLI** (`hermes_cli/`) | 702 | 🔴 High — many user-facing strings in `print()` calls |
| **Gateway** (`gateway/`) | 857 | 🔴 High — mostly logging, but some user-facing |

### Key Examples

**CLI (high impact):**
```python
# hermes_cli/main_provider_setup.py
print(f"Cleared stale OPENAI_BASE_URL from .env (was: {shown})")
print(f"Could not detect authenticated providers: {exc}")
print(f"Please enter 1-{count}")
print(f"Invalid API mode choice: {raw}. Falling back to auto-detect.")

# hermes_cli/doctor.py
print(color(f"Unknown advisory ID: {ack_target!r}. Known IDs: ...", Colors.RED))
print(color(f"  ✓ Acknowledged advisory {ack_target}. It will no longer trigger startup banners.", Colors.GREEN))
```

**Web (moderate impact):**
```tsx
// web/src/pages/WebhooksPage.tsx
title="Delete webhook"
placeholder="What this webhook does (optional)"

// web/src/pages/SystemPage.tsx
title="Restart the shared gateway?"
description="This permanently erases the selected built-in memory files. This cannot be undone."
```

**Desktop (moderate impact):**
```tsx
// apps/desktop/src/components/ui/confirm-dialog.test.tsx
title="Remove worktree?"

// apps/desktop/src/components/ui/zoomable.tsx
<ToolbarButton label="Zoom out" onClick={zoomOut}>
```

### Root Cause
The i18n system was built for **gateway replies, approval prompts, and TUI catalogs** — not for CLI output or web/desktop component strings. The `t()` function is used extensively in `gateway/` (744 matches) and `hermes_cli/` (1008 matches), but many CLI `print()` calls and web/desktop component strings bypass it.

## 3. Number Formatting: ❌ Not Locale-Aware

### Python Backend
- **No locale-aware formatting found.** Zero matches for `locale.format`, `locale.currency`, `Intl.NumberFormat`, or `LC_NUMERIC`.
- Uses raw f-string formatting: `f"{value:.0f}"`, `f"{value:.2f}"`, `f"{value:.1f}"`
- `billing_view.py:format_money()` uses `$` prefix with `,f` format specifier — **always USD, always English formatting**

```python
# agent/billing_view.py
def format_money(value: Optional[Decimal], *, grouped: bool = False) -> str:
    spec = ",f" if grouped else "f"
    if value == value.to_integral_value():
        return f"${format(value.to_integral_value(), spec)}"
    return f"${format(value.quantize(Decimal('0.01')), spec)}"
```

### TypeScript Frontend
- TUI uses `toLocaleString('en-US')` — **hardcoded to en-US**, not the user's locale
- No `Intl.NumberFormat` usage found in TUI

```ts
// ui-tui/src/components/subscriptionOverlay.tsx
credits.toLocaleString('en-US')  // Always en-US regardless of user language
```

### Impact
- A German user sees `1,234.56` instead of `1.234,56`
- A French user sees `1,234.56` instead of `1 234,56`
- Currency always shows `$` regardless of locale

## 4. Date/Time Formatting: ⚠️ Partially Locale-Aware

### Python Backend
- **Not locale-aware.** Uses `strftime` with hardcoded format strings.
- `hermes_time.py` handles timezone resolution but not locale formatting.

```python
# tools/session_search_tool.py
safe_strftime(datetime.fromtimestamp(float(ts)), "%B %d, %Y at %I:%M %p")
# Always "October 04, 2026 at 02:30 PM" — never localized
```

### TypeScript Frontend
- **Locale-aware via JS Intl API** — `toLocaleTimeString()`, `toLocaleString()` use the browser's locale
- `ui-tui/packages/hermes-ink/src/utils/intl.ts` provides `Intl.Segmenter`, `Intl.RelativeTimeFormat`, `Intl.DateTimeFormat`

```ts
// ui-tui/src/app/goalStatus.ts
new Date(epochSeconds * 1000).toLocaleTimeString([], { hour: '2-digit', minute: '2-digit' })
// This IS locale-aware — uses the runtime locale
```

### Gap
- Python backend generates timestamps for gateway replies, CLI output, and tool results — all in English
- TUI displays timestamps locale-aware, but the underlying data from Python is pre-formatted in English

## 5. Multi-Language Support: ✅ Platform-Ready

### What Works
- **17 languages** with full catalogs (YAML files in `locales/`)
- **RTL support**: Arabic (`ar`) marked as RTL in `i18n_languages.py` and `RTL_LOCALES`
- **Language picker**: Desktop and web have language switchers with endonyms
- **Plugin language packs**: Plugins can register new languages at runtime
- **User overlays**: Users can override any string via `$HERMES_HOME/locales/<lang>.yaml`
- **Profile-scoped**: Language setting is per-profile in multiplexed gateways

### Language Resolution Chain
```
HERMES_LANGUAGE env (per-profile .env)
  → display.language config
    → en (default)
```

### What's Missing
- **No automatic language detection** from browser/OS locale
- **No language fallback chain** for partial translations (e.g., `pt-br` → `pt` → `en`)
- **No pluralization framework** — English-only plural logic (`_one`/`_other` keys exist but no ICU MessageFormat)
- **No gender/grammatical agreement** support
- **No date/number locale formatting** in Python (see §3, §4)

## 6. Currency Handling: ⚠️ Present but Not Localized

### Current State
- **Currency is always USD** — no multi-currency support
- `billing_view.py` uses `Decimal` for precision (good)
- `format_money()` always prefixes with `$`
- No `Intl.NumberFormat` with `style: 'currency'` in frontend
- No exchange rate or currency conversion

```python
# agent/billing_view.py
def format_money(value: Optional[Decimal], *, grouped: bool = False) -> str:
    # Always USD, always $ prefix
    return f"${format(value.to_integral_value(), spec)}"
```

### Impact
- Non-US users see `$100.00` instead of `€85,00` or `¥15,000`
- No way to display costs in local currency
- Billing portal is USD-only

## Recommendations

### High Priority
1. **Add locale-aware number formatting to Python** — use `locale.format_string()` or `babel.numbers.format_number()` with the active language's locale
2. **Add locale-aware date formatting to Python** — use `babel.dates.format_datetime()` or `locale.strftime()` with the active language's locale
3. **Fix TUI `toLocaleString('en-US')`** — replace with `toLocaleString(undefined)` to use the runtime locale

### Medium Priority
4. **Localize CLI output** — wrap user-facing `print()` calls in `t()` for the most common commands
5. **Localize web/desktop component strings** — audit and replace hardcoded labels with i18n keys
6. **Add currency formatting** — use `Intl.NumberFormat` with `style: 'currency'` in frontend; consider multi-currency support

### Low Priority
7. **Add ICU MessageFormat pluralization** — replace `_one`/`_other` with proper plural rules
8. **Add auto language detection** — infer from browser `Accept-Language` or OS locale
9. **Add language fallback chain** — `pt-br` → `pt` → `en` for partial translations
